## 7. PHASE FOUR — CUSTOM CLOUDFLARE MCP ENDPOINT SELECTION

This is another major requested feature.

### Core requirement

MTerm-CLI must not be permanently tied to one hardcoded hosted MCP endpoint.

The owner should be able to select which authorized remote MCP endpoint or Cloudflare-backed deployment a computer or client connects to.

### Required connection modes

Design a configuration model supporting:

**Mode A — M-TechLabs managed default**

- Uses the owner's production M-TechLabs.com MCP deployment.
- Simple setup and registration.
- Centralized device management.

**Mode B — Custom Cloudflare MCP**

- User supplies an authorized Cloudflare-backed MCP URL or chooses a configured deployment.
- Supports a custom domain and MCP path.
- Supports appropriately configured Cloudflare Access authentication.
- Supports compatible Tunnel/Worker/remote MCP routing.
- Validates the endpoint and required protocol before enabling it.
- Clearly reports connection and authentication state.

**Mode C — Local/direct MCP**

- Connects to an explicitly approved local or LAN endpoint.
- Suitable for development or environments that do not require Cloudflare.
- Does not expose an unauthenticated listener to the public internet.

**Mode D — Development/staging**

- Independently configured and isolated.
- Cannot accidentally inherit production credentials or authorization grants.

### Portal requirements

Create a **Connection Profiles / MCP Endpoints** management page on M-TechLabs.com.

A profile should expose:

- Profile name.
- Type of connection.
- Server URL.
- Transport type.
- Authentication method.
- Scope and target devices.
- Health-check status.
- Last successful connection.
- Version/capability discovery.
- Secure edit/test/disable/delete controls.
- Default profile selection.
- Explicit target routing.

Where appropriate, support per-device and per-client default selection.

### Security requirements

- Validate custom URLs and protocols.
- Prevent SSRF and arbitrary internal-network proxying.
- Do not use user-provided endpoints as unrestricted backend HTTP proxies.
- Never expose service tokens or OAuth secrets to frontend JavaScript.
- Scope credentials to the selected connection.
- Prevent credential leakage between profiles.
- Verify Cloudflare Access audience and token validity where applicable.
- Support rotation and revocation.
- Respect provider-specific OAuth flows.
- Do not silently fall back from secure remote transport to insecure transport.
- Add audit logs without recording sensitive payloads.
- Require clear confirmation for cross-device or production-target operations.

Investigate appropriate support for Cloudflare Workers, Cloudflare Tunnel, Access, custom MCP server deployments, and standards-compliant remote MCP.

Do not invent Cloudflare features or claim unsupported configurations work.

### Acceptance target

A properly authorized user can register two computers, configure more than one permitted MCP profile, choose the intended connection and device, run a harmless read-only test, and see correct routing and audit records.
